# Codex task: independent arbitrary-precision reference values for the GSN arbitrary-precision acceptance tests

Prepared 2026-10-17 (GSN `ArbitraryPrecision` branch, thread "GSN 任意精度开发"). This is a self-contained
computation job for a machine with Mathematica and the Black Hole Perturbation Toolkit (BHPT) Teukolsky
paclet; it does not touch the GSN repository. Deliver plain text files (not notebooks) with full
`InputForm` digits, plus a short report. Everything below was checked on the Mac with Teukolsky paclet
1.1.1 unless marked "to do".

## 0. What the references are for

`GeneralizedSasakiNakamura.jl` now solves the homogeneous Teukolsky/GSN radial problem at arbitrary
precision (BigFloat). Every claimed precision must be measured against a reference computed
independently: the BHPT paclet's MST implementation at a *higher* working precision, with the digits
certified by agreement between two working precisions (not by Mathematica's precision tags, which are
estimates). The quantities below are normalization independent (ratios to the transmission amplitude),
so no convention for the overall amplitude is needed; the radial values are divided by the transmission
amplitude too.

**Mode parameters:** M = 1, spin weight s = -2, spins a in {2/5, 9/10}, modes (l, m) in {(2, 2), (3, 1)}.
Use exact rationals for a and omega as inputs and `SetPrecision[..., prec]` before calling the paclet.
The separation constant is `SpinWeightedSpheroidalEigenvalue[-2, l, m, a omega]` (paclet convention,
Teukolsky lambda). The radius for the radial values is the binary double
`rprime = SetPrecision[3.1126842514806725, prec]` (exactly the double, not 3.1126842514806725 rounded).

## 1. Cases

Frequencies (exact):

- real: `1/20, 1/2, 2, 10`
- complex, Re omega > 0: `1/2 - 3/10 I, 3/10 - 3/2 I, 1/2 + 3/10 I, 2 - 2 I`
- negative imaginary axis, two sides: `omega = +delta - sigma I` and `omega = -delta - sigma I` for
  `sigma in {1/10, 1/2, 1, 3}` and `delta = 10^-30`; **plus** the exact axis point `omega = -sigma I`
- positive imaginary axis: `omega = sigma I`, same sigmas

For every (a, l, m, omega): 44 real/complex cases and 2 x 2 x 4 x 4 = 64 axis cases.

**Do not compute Re omega < 0 cases.** The principal-branch MST formulas (BHPT's and ours) are not on
the physical sheet for Re omega < 0 (at -0.3 - i BHPT gives -121.5 - 46.8 i while the physical value is
conj[A^(m=-2)(0.3 - i)] = 0.2290 - 6.6567 i). The left half plane is obtained from the right one by the
symmetry (m, omega) -> (-m, -conj(omega)) with complex conjugation of the amplitudes; the GSN code does
that itself. If you want a sanity row, compute one left-half-plane point (a = 2/5, l = m = 2,
omega = -3/10 - I) and record it labelled "principal branch, NOT physical" so nobody uses it later.

## 2. Quantities per case (12 records)

With `Rin = TeukolskyRadial[-2, l, m, a, w, "BoundaryConditions" -> "In", WorkingPrecision -> prec]` and
`Rup` likewise with `"Up"`, and `ai = Rin["Amplitudes"]`, `au = Rup["Amplitudes"]`:

```
lambda                      SpinWeightedSpheroidalEigenvalue[-2, l, m, a w]
nu                          Rin["RenormalizedAngularMomentum"]
In.Incidence/Transmission   ai["Incidence"]/ai["Transmission"]
In.Reflection/Transmission  ai["Reflection"]/ai["Transmission"]
In.R(rprime)/Transmission   Rin[rprime]/ai["Transmission"]
In.dR(rprime)/Transmission  Rin'[rprime]/ai["Transmission"]
Up.Incidence/Transmission   au["Incidence"]/au["Transmission"]
Up.Reflection/Transmission  au["Reflection"]/au["Transmission"]
Up.R(rprime)/Transmission   Rup[rprime]/au["Transmission"]
Up.dR(rprime)/Transmission  Rup'[rprime]/au["Transmission"]
seconds                     wall time of the case
```

Output format, one record per line, exactly (the GSN test reader parses it):

```
a=2/5;l=2;m=2;omega=1/2 - (3*I)/10|In.Incidence/Transmission|<ToString[InputForm[value]]>
```

i.e. `tag|key|value`, tag = `"a=" <> ToString[InputForm[a]] <> ";l=" <> ... <> ";omega=" <> ToString[InputForm[omega]]`.
Keep Mathematica's precision marks (`` `41.7 ``) in the value; the reader strips them. Do not round.

A ready script that does all of this is attached: `bhpt_acceptance_reference.wls` (usage
`wolframscript -file bhpt_acceptance_reference.wls <workingprecision> <group>` with groups
`a04l2`, `a09l2`, `l3m1`, `axis`, `omega10`; the axis group has to be extended to the exact-axis and
positive-axis points, and the fallback deltas of Sec. 4). Extend it rather than rewriting the format.

## 3. Working precisions and certification

Run every case at `WorkingPrecision -> 60`, `120` and `200`; run `omega = 10` and `omega = 2 - 2 I`
additionally at `400`. For each record report the number of digits on which the two highest
precisions agree, `digits = -Log10[Abs[v_high - v_low]/Abs[v_high]]`, in a separate summary table
(`tag|key|digits_60_120|digits_120_200|digits_200_400`). The highest-precision value is the
reference; the agreement is its certified accuracy. Findings so far on the Mac (paclet 1.1.1):

- real and moderate complex frequencies: ~1-2 s per case at prec 60 (a 60-digit and a 100-digit run
  of a = 2/5, omega = 1/2 agree to ~41 digits; we need to know whether digit 41 was limited by the
  60-digit run, hence the 120/200 runs);
- `omega = 10`: at prec 60 the In amplitudes have 4 digits and the Up amplitudes are `Indeterminate`
  (`Infinity::indet`); at prec 200 the In amplitudes have ~45-65 digits and Up ~35-57, 12-17 s per
  case; at prec 400, 75-115 s per case. The large-|omega| MST sums need the higher working precision;
- `omega = 2 - 2 I`: prec 60 gives 18 digits, prec 200 ~30+;
- the radial values `R(rprime)`, `dR(rprime)` are typically 5-10 digits less accurate than the
  amplitudes at the same working precision (the paclet sums the radial series to `10^-acc`), so the
  200-digit run matters for them.

## 4. Imaginary axis: the paclet needs care

- `omega = 10^-30 - sigma I` works for `sigma = 1/10` (1.3 s, ~43 digits) but
  `TerminatedEvaluation[RecursionLimit]` ends the whole kernel evaluation for `sigma >= 1/2`
  (seen at prec 60, 120 and 200; `$RecursionLimit = 65536` did not help; `CheckAbort` does not catch
  it). `omega = 10^-10 - I/2` works (1.8 s). `omega = 10^-20 - I/2` fails. The exact axis point
  `omega = -I/2` did not return within 300 s.
- Requested: for each sigma find the smallest delta in {10^-6, 10^-10, 10^-15, 10^-20, 10^-30} for
  which both signs of delta succeed, record all deltas that worked (the jump across the axis is
  needed as a function of delta, so keep every successful delta, not only the smallest), and report
  which step fails (try `SpinWeightedSpheroidalEigenvalue` and `RenormalizedAngularMomentum` separately
  before `TeukolskyRadial`; try `Method -> "Monodromy"` for nu if the paclet version offers it). Wrap
  each case in `TimeConstrained[..., 600]` and run each case in a fresh kernel (`wolframscript` per
  case, or `Quit[]` between cases) so one failure does not end the batch.
- The exact axis points `-sigma I` and `+sigma I`: run with a 1-hour limit each; if the paclet does
  not return, say so and give the two-sided limits instead.

## 5. Quasinormal frequencies (to do, two independent methods)

For s = -2, l = m = 2, a in {2/5, 9/10}, overtones n = 0..9: the frequencies to >= 60 digits, and the
frequency derivative of the In incidence amplitude at each root.

1. If the BHPT `QuasiNormalModes` paclet is available (`PacletInstall["QuasiNormalModes"]`), use it with
   a working precision of at least 80 and record its convention (overtone labelling of the a = 2/5,
   n = 8 pair near -2i, and the Schwarzschild continuation; GSN follows the Python `qnm`/Cook
   convention, see `docs/QNM.md` in the repository).
2. Independently, implement Leaver's method in Mathematica at `WorkingPrecision -> 100`: the angular
   continued fraction (or `SpinWeightedSpheroidalEigenvalue`) coupled with the radial continued
   fraction (Leaver 1985; inversion index = n), `FindRoot` from a double-precision seed (the GSN
   repository's `test/extended/data/qnm_references.jl` has seeds for a = 0.4, 0.9; the Python package
   `qnm` gives them too). Report `|cf(omega)|` at the root and the agreement with method 1.
3. `dA_inc/domega` at each root, Teukolsky normalization ("Incidence/Transmission" of the In solution):
   fourth-order central difference `(f(w-2h) - 8 f(w-h) + 8 f(w+h) - f(w+2h))/(12 h)` with
   `h = 10^-15 |omega|` at `WorkingPrecision -> 120`, plus the same with `h = 10^-12 |omega|` as a check;
   report the digits on which the two agree. Also report `A_inc(omega_n)` itself at prec 120 (it must
   be small; its size divided by |dA_inc/domega| is the root error).
